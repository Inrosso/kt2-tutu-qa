# Проверка результата с позиции аналитика данных

Моя смежная роль по КТ1 — аналитик данных.

## Как взаимодействуют QA и аналитик данных

QA передаёт результаты проверок, примеры входных данных и описание найденных проблем. Аналитик данных помогает сгруппировать результаты, увидеть повторяющиеся ситуации и понять, какие проблемы чаще всего встречаются.

## Замечание 1. Не хватало общей сводки результатов

В первоначальном Word-документе фактические результаты были записаны внутри каждого тест-кейса. Чтобы понять общую картину, приходилось просматривать весь документ.

**Почему это важно:** по одной общей сводке проще увидеть соотношение пройденных и непройденных проверок и определить основные группы проблем.

**Что я добавил:** отдельный файл `test-results-summary.md` с количеством результатов и кратким описанием основных наблюдений.

## Замечание 2. В некоторых кейсах объединено несколько значений

Например, в TC-AGE-17, TC-AGE-21, TC-AGE-26 и TC-AGE-27 проверяется несколько вариантов ввода. Если записать только общий результат, сложно понять, на каком именно значении возникла проблема.

**Почему это важно:** без детализации трудно повторить конкретный случай и сравнить варианты между собой.

**Что я добавил:** отдельный файл `subcase-results.md`, где фактическое поведение записано отдельно для каждого значения.

## Замечание 3. Нужно отделять подтверждённые несоответствия от наблюдений

В TC-AGE-14 числовой расчёт правильный, но в подписи есть ошибка «Мне 2 лет». В TC-AGE-23 и TC-AGE-32 поведение не полностью определено исходным заданием.

**Почему это важно:** если смешать эти случаи с обычными ошибками расчёта, общая статистика будет неточной.

**Что я добавил:** в `test-results-summary.md` и `observed-issues.md` отдельно описал ошибку подписи и случаи, для которых в исходном задании нет точного требования.

## Что изменилось после этой проверки

Теперь результаты можно посмотреть на трёх уровнях:
1. Общее количество пройденных и непройденных кейсов — `test-results-summary.md`.
2. Подробности по конкретным проблемам — `observed-issues.md`.
3. Результаты отдельных значений в составных кейсах — `subcase-results.md`.

Изменения по этим замечаниям опубликованы в коммите [a97e7a4](https://github.com/Inrosso/kt2-tutu-qa/commit/a97e7a4). В нём добавлены общая сводка результатов, описание наблюдений и отдельные результаты для значений из составных тест-кейсов.
